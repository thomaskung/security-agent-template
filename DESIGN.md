# Security Agent Architecture Design

## 1. Overview
This document outlines the architecture and design for a conversational security agent built using the LangChain ecosystem. The agent is designed to continuously learn and improve by researching topics, analyzing documents, and maintaining long-term memory. 

The system leverages a **Supervisor/Router pattern**, where a main agent coordinates three specialized subagents: a Research Agent, a Reading Agent, and a Learning Agent.

## 2. Tech Stack & Components
*   **Core Framework:** LangChain & LangGraph (DeepAgents)
*   **User Interface:** LangChain Deep-Agents-UI (React-based conversational UI)
*   **LLM Provider:** Fireworks AI Serverless API hosting **Kimi 2.6**
*   **Web Search:** Tavily API
*   **Document Parsing:** Microsoft `markitdown`
*   **Vector Database (Memory):** ChromaDB (Local SQLite instance)
*   **State & Interrupts:** LangGraph native `interrupt` for Human-in-the-Loop (HITL)

## 3. Architecture & Orchestration

The system follows a hierarchical structure:

### Main Agent (Supervisor)
The Main Agent serves as the primary conversational interface for the user via the Deep-Agents-UI. It acts as a router, analyzing the user's input and delegating the task to the appropriate subagent. It manages the conversational state and ensures that subagent tasks (especially long-running research) are executed sequentially to prevent context collision.

### Subagents
The Supervisor routes requests to one of three specialized subagents:

#### 1. Research Agent
*   **Purpose:** Searches the internet for security-related information and synthesizes comprehensive research reports.
*   **Tooling:** Tavily Search API.
*   **Workflow:** 
    *   Receives a topic from the Main Agent.
    *   Executes search queries sequentially (one topic at a time).
    *   The Main Agent blocks/waits until the Research Agent finishes compiling its final report in Markdown format.

#### 2. Reading Agent
*   **Purpose:** Processes unstructured and structured documents (Word, Excel, PDF, CSV, Markdown, HTML, XML).
*   **Tooling:** Microsoft `markitdown`.
*   **Workflow:**
    *   Receives a file path or document buffer.
    *   Converts the document into standardized Markdown using `markitdown`.
    *   Analyzes the Markdown content to summarize and extract key takeaways relevant to the agent's security persona.
    *   Outputs a structured reading report. Processes one document at a time.

#### 3. Learning Agent
*   **Purpose:** Evaluates reports generated by the Research and Reading agents to determine if the information is valuable for long-term retention.
*   **Tooling:** ChromaDB (Local), LangGraph `interrupt`.
*   **Workflow:**
    *   Reviews incoming reports for relevance to the security context.
    *   **Human-in-the-Loop (HITL):** Before committing any new knowledge to the vector database, the agent triggers a LangGraph `interrupt`. This pauses the execution graph and prompts the user in the Deep-Agents-UI for approval.
    *   Upon user approval, the agent embeds the report and updates the local ChromaDB instance.
    *   This stored knowledge is then accessible to the Main Agent via RAG (Retrieval-Augmented Generation) for future conversations, enabling continuous improvement.

## 4. Security & Configuration
All sensitive configurations and API keys must be strictly managed via environment variables. A `.env` file will be used locally to store:

```env
# API Keys
FIREWORKS_API_KEY="your_fireworks_api_key_here"
TAVILY_API_KEY="your_tavily_api_key_here"

# LangSmith Tracing
LANGCHAIN_TRACING_V2="true"
LANGCHAIN_API_KEY="your_langsmith_api_key"
LANGCHAIN_PROJECT="security-agent"
```
*(Note: The `.env` file must be added to `.gitignore` and never committed to source control.)*

## 5. Continuous Improvement Cycle
1. **Acquire:** The Research and Reading agents pull in new external context.
2. **Evaluate:** The Learning Agent assesses the quality and relevance of the context.
3. **Verify:** The Human-in-the-Loop approves the context via the UI.
4. **Store & Retrieve:** The validated context is stored in ChromaDB and injected into the Main Agent's prompt context (RAG) for all subsequent user interactions.
